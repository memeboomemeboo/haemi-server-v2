### 범례
- **액터**: 비회원 / 회원 / 보호자 / 어르신
- **상태**: 시작 전 · 진행 중 · 대기 · 완료 (미기재 = Notion에 상태 미지정)
- **모듈**: v2 구현 위치. ⚠️ Notion 원문이 아니라 [v2 구조](./v2-module-architecture.md)에 따른 **추가 표기**입니다.
  - `A + B` — 두 모듈이 함께 처리
  - `A → B` — A가 B를 호출 (동기)
  - `A ← B` — A가 B의 결과를 받음 (조회 또는 이벤트)
- 기능ID가 없는 항목은 Notion 원문에도 ID가 비어 있습니다.

## 1. 인증

### 1.1 ACC — 회원/계정

#### ACC-REG-001 · 회원가입 (보호자)
- **액터**: 비회원, 보호자 · **상태**: 시작 전
- **모듈**: `auth/account` · `auth/credential` · `auth/verification`
- **설명**: 이메일 인증을 통해 본인 확인 후 계정을 생성한다.
- **입력값**
  - 이름
  - ID
  - PW
  - 생년월일
  - 전화번호
  - 간편 PIN 6자리

#### ACC-REG-002 · 회원가입 (어르신)
- **액터**: 비회원, 어르신 · **상태**: 시작 전
- **모듈**: `auth/account` ← `guardian/eldermanagement` 가 요청
- **설명**: 보호자의 마이페이지에서 '어르신 등록하기'를 통해 계정을 생성한다.
- **입력값**
  - 이름
  - 성별
  - 전화번호
  - ID
  - PW
  - 간편 PIN 6자리
  - (role: elder)

#### ACC-LGN-001 · 로그인 (보호자)
- **액터**: 회원, 보호자 · **상태**: 시작 전
- **모듈**: `auth/session` · `auth/credential`
- **설명**: ID, PW와 PIN으로 사용자 인증 후 로그인한다.
- **비고**: (첫) ID, PW / (이후) 간편 PIN 6자리

#### ACC-LGN-002 · 로그인 (어르신)
- **액터**: 회원, 어르신
- **모듈**: `auth/session` · `auth/credential`
- **설명**: 어르신은 계정 생성 시부터 6자리 간편 PIN으로 로그인한다. 보호자가 등록 시 6자리 크리덴셜을 설정하며, 이 값이 PIN이자 비밀번호로 쓰인다.
- **비고**: 계정 생성부터 `loginId + PIN 6자리`. (2026-08-27 확정 디자인 X2 반영 — 어르신 크리덴셜 6자리 단일값 통일, PR #103. 이전 문구 "최초 ID/PW, 이후 PIN"은 확정 디자인 이전 기준으로 폐기됨)

#### ACC-LGN-003 · 로그아웃
- **액터**: 회원, 보호자, 어르신 · **상태**: 시작 전
- **모듈**: `auth/session`
- **설명**: 로그인 세션을 종료하고 저장된 인증 정보를 제거한다.
- **비고**: 기본적으로 현재 기기만 로그아웃

#### ACC-LGN-004 · 얼굴 인증
- **액터**: 회원, 어르신 · **상태**: 대기
- **모듈**: `auth/session`
- **설명**: 기기에 등록된 얼굴로 본인 여부를 확인한다.
- **비고**: 기기 OS Face ID 사용

### 1.2 ALM — 알림
- **상태**: 대기
- Notion에 카테고리 행만 존재하고 하위 기능이 정의되어 있지 않습니다.

## 2. 보호자

### 2.1 HOME — 홈

#### 어르신 정보
- **액터**: 회원, 보호자
- **모듈**: `guardian/presentation` (조합) ← `guardian/eldermanagement` + `elder/attendance`
- **설명**: 어르신의 정보를 볼 수 있다. 어르신이 여러 명인 경우, 섹션으로 묶어 표시된다.
- **표시 항목**
  - 어르신과 함께한 일 수
  - 어르신의 연세
  - 어르신의 오늘 출석 여부

#### 어르신께 하루 한마디
- **액터**: 회원, 보호자 · **상태**: 시작 전
- **모듈**: `guardian/dailycare` → `elder/inbox`
- **설명**: 어르신께 보호자가 음성 혹은 텍스트를 선택하여 하루에 한 마디를 전할 수 있다.
- **규칙**
  - 음성 혹은 텍스트 중 1택
  - 음성 1분 이하
  - 텍스트 100자 이하
  - 하루 한 마디를 전할 어르신 선택 가능
  - 가족에 등록된 어르신의 수 만큼 하루 한 마디 전할 수 있음

#### 도전과제
- **액터**: 회원, 보호자
- **모듈**: `guardian/dailycare`
- **설명**: 보호자에게 일일 도전 과제를 제공한다.
- **과제**
  - 하루 한마디
  - 추억 앨범 등록하기

### 2.2 ALB — 추억 앨범 (보호자)

#### 추억 앨범 등록
- **액터**: 회원, 보호자 · **상태**: 시작 전
- **모듈**: `guardian/memory` + `platform/media`
- **설명**: 추억 앨범을 등록한다.
- **입력값**
  - 추억명
  - 추억 메모 (최대 300자) — "추억의 내용을 구체적으로 작성해주세요"
  - 추억 이미지 (최대 4장)
  - 어르신과의 추억 한마디 — "어르신께 추억의 한마디를 전달해보세요"
  - 보낼 어르신 — 가족에 속한 어르신들 중, 어느 어르신께 보낼지 선택할 수 있다.
  - 추억 연도 (선택)
  - (등록일, 생성자)

#### 추억 앨범 조회
- **액터**: 회원, 보호자 · **상태**: 시작 전
- **모듈**: `guardian/memory`
- **설명**: 추억 앨범을 조회한다. 최대 1년간의 추억들을 조회할 수 있다.
- **비고**
  - (조회) 추억명, 추억 이미지, 어르신 답변 여부
  - (상세 조회) 등록 시 입력한 모든 정보 조회

#### 어르신 답변 조회
- **액터**: 회원, 보호자 · **상태**: 시작 전
- **모듈**: `guardian/memory` ← `elder/response`
- **설명**: 추억 앨범에 응답한 어르신의 답변을 조회한다.
- **비고**: (조회) 어르신의 텍스트 / 이미지 / 음성 응답을 조회할 수 있다.

### 2.3 MYP — 마이

#### 프로필 조회
- **액터**: 회원, 보호자 · **상태**: 시작 전
- **모듈**: `guardian/presentation` (조합) ← `auth/account` + `guardian/family` + `guardian/eldermanagement`
- **설명**: 로그인한 사용자의 프로필 정보와 계정 및 기타 설정 정보를 조회한다.
- **비고**
  - (조회) 이미지, 이름, 전화번호, ID, 생년월일
  - 로그인한 보호자 본인 프로필만 조회 가능
  - (가족) 속한 가족을 조회
    - 가족명, 가족 프로필 이미지
    - (상세 조회) 생성 시 입력한 정보와 가족에 속한 어르신 조회
  - (연결 어르신) 연결된 어르신을 카드 형태로 조회

#### 프로필 수정
- **액터**: 회원, 보호자 · **상태**: 시작 전
- **모듈**: `auth/account` + `guardian/eldermanagement` (역할 라벨)
- **설명**: 사용자의 프로필 이미지와 아이디를 수정한다.
- **규칙**
  - 실명 수정 불가
  - 아이디 3자 ~ 20자
  - 아이디 중복 불가
  - 생년월일
    - 1920년부터 제공
  - 앨범 이미지 사용
  - 가족 프로필
  - 보호자 역할 선택 (등록한 어르신마다 어르신에 대한 보호자의 역할을 선택할 수 있다.)
    - 보호자, 딸, 아들, 손녀, 손자
    - 기타 (ex. 며느리, 배우자 등)

#### 가족 생성
- **액터**: 회원, 보호자 · **상태**: 시작 전
- **모듈**: `guardian/family`
- **설명**: 가족을 생성한다.
- **입력값**
  - 가족명
  - 가족 메모 (최대 30자)
  - 가족 프로필 이미지
  - 어르신 추가
    - 등록한 어르신을 가족에 추가할 수 있다.
    - 가족에는 최대 4명의 어르신을 추가할 수 있다.
  - (가족에는 고유한 ID가 부여된다.)
- **2026-08-24 확정 보완**
  - 가족 생성 시 보호자 합류용 초대 코드를 함께 발급한다.
  - 어르신은 초대 대상이 아니며, 다른 보호자만 초대 코드로 합류한다.
  - 보호자는 한 가족에만 속하므로 가족 목록·상세 API를 나누지 않는다. 현재 보호자의 가족 정보·보호자 구성원·어르신 목록을 단일 조회 응답으로 제공하고 화면 분할은 프론트에서 처리한다.

#### 어르신 계정 생성
- **액터**: 회원, 보호자 · **상태**: 시작 전
- **모듈**: `guardian/eldermanagement` → `auth/account`
- **설명**: '어르신 등록하기'를 통해 계정을 생성한다.
- **비고**: ACC-REG-002 참고

### 2.4 RPT — 리포트

#### RPT-LST-001 · 어르신 리포트 목록
- **액터**: 회원, 보호자 · **상태**: 시작 전
- **모듈**: `guardian/report`
- **설명**: 가족에 속한 어르신(최대 4명)을 카드로 모아 보고, 개별 리포트로 전환한다.
- **규칙**
  - 가족에 속한 어르신 최대 4명을 카드 리스트로 표시 (HOME "어르신 정보" 섹션 구조 재사용)
  - 카드 1개 = 이름 · 어르신과의 관계 라벨(딸/아들/손녀 등) · 연세 · 오늘 출석(●/○) · 종합상태 배지(🟢🟡🟠)
  - 정렬: 🟠 관찰필요 → 🟡 → 🟢 순 (서포트 우선순위 상단 노출)
  - 어르신 1명이면 목록 생략하고 바로 `RPT-SUM-002` 진입 ※ 해당 ID 미존재 — [부록 B](#부록-b-명세-결손-목록) 참조
  - 카드 탭 → 해당 어르신 상세 리포트로 전환
  - 어르신 간 점수 비교·순위 미제공 (각자 본인 기준선 대비로만 평가)

#### RPT-LST-002 · 어르신 요약 카드
- **액터**: 회원, 보호자 · **상태**: 시작 전
- **모듈**: `guardian/report`
- **설명**: 선택한 어르신의 연세·함께한 일 수·출석·종합상태를 상단에 고정 표시한다.
- **규칙**
  - 연세: 만 나이 + 세대 태그 (예: "78세 · 70대")
  - 함께한 일 수: 첫 등록일부터 D+정수
  - 오늘 출석: 완료/미완료
  - 이번 주 참여: "7일 중 4일" + 링 게이지
  - 종합상태: 🟢좋음 / 🟡보통 / 🟠관찰필요 (`RPT-COG-004` 규칙 기반) ※ 해당 ID 미존재 — [부록 B](#부록-b-명세-결손-목록) 참조
  - 상단에 현재 보고 있는 어르신 이름 고정 + 다른 어르신으로 빠르게 전환하는 드롭다운

#### RPT-ATT-003 · 출석 및 참여 현황
- **액터**: 회원, 보호자 · **상태**: 시작 전
- **모듈**: `guardian/report` ← `elder/attendance` 이벤트
- **설명**: 해당 어르신의 최근 7일 및 최근 4주 참여일을 시각화한다.
- **규칙**
  - 주간 권장 목표: 주 5일
  - 표시 창: 최근 7일 + 최근 4주
  - 시각화: 요일별 완료 점(●/○), 4주 막대
  - 스트릭: 연속 참여일 + 최고 기록
  - 상태 규칙: 주 5일↑ 🟢 / 3~4일 🟡 / 2일↓ 🟠
  - 데이터는 어르신별 독립 집계

#### RPT-ATT-004 · 인지 영역별 상태
- **액터**: 회원, 보호자 · **상태**: 시작 전
- **모듈**: `guardian/report` ← `elder/training` 이벤트
- **설명**: 인지 훈련 결과를 쉬운 언어로 번역해 영역별 상태로 표시한다.
- **규칙**
  - 내부 점수 미노출, 본인 기준선 대비 추세 + 3색 라벨로만 번역
  - 표시 영역
    - "날짜·요일 감각" (지남력) ← CIST-TRN-002
    - "옛 기억 떠올리기" (회상) ← CIST-TRN-003
    - "말로 표현하기" (언어) ← CIST-TRN-004
    - "회상하기" (지연 회상, 별도 강조) ← CIST-TRN-005
  - 상태 기준 (영역별 독립)
    - 최근 7일 정답률 ≥ 70% 🟢
    - 최근 7일 정답률 40~70% 🟡
    - 최근 7일 정답률 < 40% 또는 4주 연속 하락 🟠
  - 문구 톤: 🟠도 "나쁨"이 아니라 관찰·서포트 신호 ("요즘 조금 어려워하세요")
  - 진단명·등수·타 어르신 비교 절대 미노출

#### RPT-ATT-005 · 이번 주 하이라이트
- **액터**: 회원, 보호자 · **상태**: 시작 전
- **모듈**: `guardian/report`
- **설명**: 해당 어르신의 잘한 점 및 변화를 1~3줄로 요약한다.
- **규칙**
  - 해당 어르신 1주 데이터에서 자동 생성되는 1~3줄
  - 예: "이번 주 5일 참여하셨고, 옛 기억 떠올리기를 특히 잘하셨어요."
  - 잘한 점 먼저 → 변화 관찰 순 (정서 배려)

#### RPT-ATT-006 · 서포트 가이드
- **액터**: 회원, 보호자 · **상태**: 시작 전
- **모듈**: `guardian/report`
- **설명**: 상태에 맞춰 보호자가 할 수 있는 행동을 제안한다.
- **규칙**
  - 상태 트리거 → 기존 기능 연결 행동 제안
  - 참여 2일↓ → "하루 한마디 보내기로 응원해보세요" (HOME에 표시)
  - 옛 기억 🟠 → "추억 앨범에 가족 사진을 올려보세요" (E-ALB 연결)
  - 지연 회상 하락 → "안부 전화로 오늘 있었던 일을 여쭤보세요"
  - 전반 🟢 → "칭찬 한마디를 전해보세요"
  - 제안 대상 어르신 이름을 명시 (예: "황정빈 어르신께 추억 사진을…")

## 3. 어르신

### 3.1 CIST — 인지 문제

> 정량 규격은 [4. 인지 훈련 (CIST) 정량 명세](#4-인지-훈련-cist-정량-명세) 참조

#### CIST-TRN-001 · 인지 훈련 시작
- **액터**: 회원, 어르신
- **모듈**: `elder/training/session`
- **설명**: 하루에 한 번 인지 훈련 세션에 진입한다.
- **규칙**
  - 하루 1회 제공 (자정 기준 리셋, 완료 후 당일 재진입 시 결과만 조회)
  - 미완료 세션은 이어하기 가능 / 완료 시 잠금
  - 세션 = 지남력 → 기억 회상 → 언어 → 지연 회상 순으로 구성
  - 소요 시간 약 5~10분, 도중 이탈 시 진행 지점 저장

#### CIST-TRN-002 · 지남력 훈련
- **액터**: 회원, 어르신
- **모듈**: `elder/training/question`
- **설명**: 지남력 훈련
- **규칙**
  - 문항 유형: 오늘 며칠 / 무슨 요일 / 올해 몇 년도 / (변형) 다음 주 같은 요일은 며칠
  - 실제 기기 날짜와 대조하여 즉시 피드백
  - 콘텐츠 데이터 없이도 항상 생성 가능 (세션의 뼈대)

#### CIST-TRN-003 · 기억 회상 훈련
- **액터**: 회원, 어르신
- **모듈**: `elder/training/question` ← `platform/content` · `guardian/memory`
- **설명**: 기억 회상 훈련
- **규칙**
  - 재료 우선순위: ① 가족이 등록한 추억 앨범 → ② 큐레이션 콘텐츠 풀
  - 인물 회상(가족 이름 등)은 MVP 제외 → 콘텐츠/추억 이미지 기반 회상만
  - 문항 예: "이 사진은 몇 년도쯤일까요?" / "사진 속 물건은 무엇일까요?" / "따님의 이름은 어떻게 되시나요?"
  - 콘텐츠 태그(era, region, recommendedAge)로 어르신에게 맞는 항목만 노출
  - 정답 데이터: 연도, 이름/키워드, 카테고리

#### CIST-TRN-004 · 언어 훈련
- **액터**: 회원, 어르신
- **모듈**: `elder/training/question` ← `platform/content` · `guardian/memory`
- **설명**: 언어 훈련
- **규칙**
  - 추억 앨범 이미지를 활용해 이름대기·짧은 설명·회상 대화 형태로 진행
  - 추억 앨범이 비어 있으면 큐레이션 콘텐츠로 대체
  - 텍스트/음성 응답 모두 허용, 정오답 채점보다 참여 완료 중심

#### CIST-TRN-005 · 지연 회상
- **액터**: 회원, 어르신
- **모듈**: `elder/training/delayedrecall`
- **설명**: 지연 회상
- **규칙**
  - CIST-TRN-003/004에서 노출된 항목 중 1~2개를 세션 마지막에 재질문
  - 임상적으로 의미 있는 지표라 결과 기록에 별도 표시
  - 같은 콘텐츠를 다른 질문 프레임으로 재사용 (연도 → 이름대기 → 회상)

#### CIST-TRN-006 · 훈련 결과 확인
- **액터**: 회원, 어르신
- **모듈**: `elder/training` + `elder/attendance`
- **설명**: 훈련 결과를 확인한다.
- **규칙**
  - 오늘 완료 여부, 참여 시간, 지연 회상 성공 여부 표시
  - 보호자 화면(HOME 어르신 정보)의 "오늘 출석 여부"와 연동 가능

### 3.2 FRI — 말동무
- **상태**: 대기
- Notion에 카테고리 행만 존재하고 하위 기능이 정의되어 있지 않습니다.

### 3.3 E-ALB — 추억 앨범 (어르신)

#### 추억 앨범 조회
- **액터**: 회원, 어르신 · **상태**: 시작 전
- **모듈**: `elder/memory` ← `guardian/memory` (조회 전용)
- **설명**: 추억 앨범을 조회한다. 최대 1년간의 추억들을 조회할 수 있다.
- **비고**
  - (조회)
    - 추억명
    - 추억 이미지
    - 추억 생성자 (관계, 이름)
    - 본인 답변 여부
  - (상세 조회) 등록 시 입력한 모든 정보 조회

#### 추억 앨범 답변
- **액터**: 회원, 어르신 · **상태**: 시작 전
- **모듈**: `elder/response` + `platform/media`
- **설명**: 추억 앨범에 대해 답변한다. 마음 전하기, 텍스트 및 이미지의 댓글, 음성 등의 답변을 보낼 수 있다.
- **마음 전하기**
  - 사랑, 행복, 즐거움, 그리움, 슬픈, 보고싶은, 화난
  - 위의 감정 중 최대 2개를 선택하여 앨범에 대해 반응할 수 있다.
- **댓글**
  - 텍스트 (최대 100자)
  - 이미지
- **음성**
  - 최대 1분의 음성 메시지
  - 입력 중 멈춤 불가능 (어르신에게 기호가 아닌 글로 안내하기 위해)
  - "이렇게 보낼게요 | 다시 녹음해요"

## 4. 인지 훈련 (CIST) 정량 명세

> Notion 하위 페이지 🍀 "인지 훈련 (CIST) 정량 명세" 전문

### 4.1 세션 구조 (하루 1회)

| 항목 | 값 |
| --- | --- |
| 제공 빈도 | 1일 1세션 (00:00 KST 리셋) |
| 총 문항 수 | 10문항 |
| 구성 | 지남력 3 · 기억 회상 3 · 언어 2 · 지연 회상 2 |
| 진행 순서 | 지남력 → 기억 회상 → 언어 → 지연 회상 |
| 목표 소요 시간 | 5~8분 (문항당 평균 30~45초) |
| 문항당 제한시간 | 없음(어르신 배려) / 90초 무입력 시 음성 재안내 |
| 이탈 처리 | 진행 지점 저장, 당일 재진입 시 이어하기 |
| 완료 판정 | 10문항 응답 완료 시 잠금, 당일 재진입은 결과 조회만 |
| 오답 페널티 | 없음 (정서 배려) |

### 4.2 문항별 정량 규격

| 영역 | 문항 수 | 세부 값 |
| --- | --- | --- |
| 지남력 | 3 | 4지선다, 보기 4개 고정 |
| 기억 회상 | 3 | 이미지 1장 + 4지선다 or 3택 |
| 언어 | 2 | 이미지 1장 + 이름대기(주관식/음성) |
| 지연 회상 | 2 | 앞 회상·언어 항목 중 2개 재출제 |

### 4.3 난이도 (3단계 자동 조절)

| 레벨 | 명칭 | 보기 수 | 연도 정답 허용오차 | 힌트 |
| --- | --- | --- | --- | --- |
| Lv.1 | 쉬움 | 3택 | ±10년 | 제공 |
| Lv.2 | 보통 | 4택 | ±5년 | 없음 |
| Lv.3 | 어려움 | 4택 | ±3년 | 없음 |

- 시작 레벨: **Lv.1**
- 상향: 최근 **2일 연속 정답률 ≥ 80%** → +1레벨
- 하향: **정답률 ≤ 40%** → −1레벨 (즉시)
- 레벨은 영역별로 독립 관리 (지남력 Lv.3, 회상 Lv.1 같은 상태 허용)

### 4.4 콘텐츠 풀·재출제 정량값

> Notion 원문 제목: "콘텐츠 풀·재출제 정량값 (CIST-TRN-101 내부 로직)"
> ※ `CIST-TRN-101` 행은 DB에 존재하지 않습니다 — [부록 B](#부록-b-명세-결손-목록) 참조

| 파라미터 | 값 | 의미 |
| --- | --- | --- |
| 전체 큐레이션 풀 | 500개 (MVP) | 시드 |
| 유저별 eligible 풀(추정) | 150~200개 | `region=KR` + `recommendedAge` + `era` 필터 후 |
| 최근 사용 쿨다운 | **7일** | 최근 7일 출제 항목 제외 |
| 지연 회상 재투입 창 | **14~30일** | 쿨다운 지난 것 중 가장 오래된 것부터 |
| 세션당 신규 콘텐츠 소비 | 3~5개 | 회상+언어 재료 |
| 풀 고갈 임계 | eligible < 20개 | 이하로 떨어지면 쿨다운 무시하고 재투입 |
| 소스 우선순위 | 추억앨범(E-ALB) → 큐레이션 | 앨범 비면 큐레이션 fallback |
| 콘텐츠 만료 | `availability.until` 경과 시 자동 제외 | 세션 로직 무영향 |

### 4.5 결과 기록 (CIST-TRN-006, 참여 중심)

| 지표 | 값/형식 |
| --- | --- |
| 완료 여부 | boolean |
| 참여 시간 | 초 단위 기록 |
| 지연 회상 성공 | 2문항 중 성공 개수 (0~2) |
| 연속 참여일(스트릭) | 정수, 자정 미완료 시 리셋 |

## 5. 가입 플로우

> Notion 하위 페이지 🧣 "가입 플로우" 전문

**가입 플로우는 이렇게 잡는 것을 추천합니다.**

### 보호자가 먼저 가입하는 경우

```text
보호자 회원가입
      ↓
보호자 기본정보 입력
      ↓
보호자 홈
      ↓
"어르신 등록하기"
      ↓
어르신 정보 입력
      ↓
어르신 가입/본인확인
      ↓
어르신 계정 생성
```

여기서 중요한 것은 **보호자가 입력했다고 해서 보호자 계정 아래에 어르신을 종속시키지 않는 것**입니다.
보호자가 입력한 정보로 **어르신 User를 생성**하는 것입니다.
