## 0. 디자인 화면 전수 목록 (33장)

- **보호자**: 회원가입(정보입력+PIN설정), PIN 로그인, 마이페이지, 프로필 수정, 어르신 등록, 가족 생성(초대코드), 우리 가족, 보호자 홈, 추억 앨범(빈/어르신필터/목록), 추억 등록, 추억 상세(사진·메모·주고받은 이야기), 리포트 목록, 리포트 상세(요약/출석·참여/인지 영역별 상태/이번 주 하이라이트/서포트 가이드), 하루 한마디(메모/음성 녹음/재생)
- **어르신**: PIN 로그인, 어르신 홈(3가지 상태), 추억 앨범 목록, 이야기 전하기(방식 선택), 이야기 말하기(음성), 마음 전하기(감정), 완료

## 1. 🔴 서버에 없는 API (신규 구현 필요)

| # | 디자인 근거 | 필요한 동작 | 현재 서버 | 제안 |
| --- | --- | --- | --- | --- |
| **M1** | **회원가입 · 프로필 수정 · 어르신 등록**의 `아이디` 옆 **"중복 확인"** 버튼 (3곳) | 제출 전 loginId 사용 가능 여부 조회 | 없음. loginId 중복은 **제출 시점 409**로만 검증 | `GET /api/v1/auth/login-id/availability?loginId=...` 신설 |

| **M3** | **보호자 홈**의 **"오늘 컨디션 좋아요 · 양호"** 링(어르신 드롭다운별) | 선택 어르신의 **오늘 컨디션 상태(양호/주의/관찰)** 를 홈에서 표시 | 없음. 홈 응답에 컨디션 상태 필드 없음(리포트 cognitive-status는 별도·주간 단위) | 홈 `ElderCard`에 컨디션 상태 추가 or 홈 전용 요약 필드 신설 |
| **M4** | **추억 앨범**의 **"전체" 탭** (김순자/박영호와 함께 상단 필터) | **전 어르신 추억 통합 목록** 조회 | `GET /api/v1/guardian/memories`는 `elderId` **필수** → 통합 조회 불가 | `elderId` 옵셔널화(미지정 시 전체) or 통합 목록 API 신설 |
| **M5** *(조건부)* | **리포트 상세**의 "이번 주 하이라이트" 카드에 **연필(편집) 아이콘** | 보호자가 하이라이트 문구 편집 | `GET /report/highlight`만 존재, 수정 API 없음 | 편집이 실제 기능이면 `PATCH .../report/highlight` 필요 (단순 표시면 무시) |

## 2. 🟡 있지만 디자인과 안 맞는 API (계약 수정 필요)

| # | 화면 | 디자인 | 현재 서버 | 갭 / 조치 |
| --- | --- | --- | --- | --- |
| **X1** | **보호자 회원가입** | `이름·생년월일·아이디(+중복확인)·비밀번호` → 2단계 `PIN 설정`. **이메일·전화번호·이메일 인증 없음** | `POST /auth/guardians/register` 가 **email, emailVerificationId, phone 모두 필수** | 디자인에 email/phone/이메일 인증 자체가 없음 → 회원가입 요청에서 **email·emailVerificationId·phone 제거**, 이메일 인증 플로우(§4) 미사용 |
| **X2** | **어르신 등록 / 어르신 로그인** | 자격증명이 **단일 `비밀번호`** 하나(로그인 화면도 "비밀번호 6자리") | `RegisterElderRequest` 가 **`password`**(8자 이상) + **`pin`**(6자리)를 **둘 다** 요구 | 어르신은 6자리 단일 크리덴셜로 통일 필요(현재는 password+pin 이중, 디자인 폼엔 PIN 설정 단계도 없음) |
| **X3** | **추억 상세 – 주고 받은 이야기** | 답변 카드 = `작성자·작성시각` + `감정 태그(그리움/행복)` + `텍스트` + `음성 재생` 을 **한 단위**로 표시 | `ResponseItem{ id, responseType, emotions, text, mediaKey }` — **답변별 단일 타입**, `createdAt`(시각)·전사 텍스트 없음 | ① 시각(`createdAt`) 필드 추가 필요(디자인이 "2일전·오후 3:20" 표시) ② 음성 밑 인용문이 전사면 전사 필드 필요 ③ 감정+음성 한 카드 = 프론트 병합 전제인지 명확화 |
| **X4** *(확인)* | **추억 앨범 목록** 카드 "**구지면 · 1980.04.**" | 장소(구지면) + 연·월 표시 | `RegisterMemoryRequest.memoryYear` 는 **정수(연도만)**, 장소 필드 없음 | 등록 폼(연도 아래 미확인)에 **장소 입력이 있으면** 서버에 `place`·`month` 추가 필요 → 폼 하단 확인 요망 |

> **정정(2026-08-30, 사용자 결정 + 확정 디자인 3쪽)**: 프로필 수정 화면의 `이름·생년월일`은 저장 버튼과 함께 제공되는 수정 필드다. 특히 생년월일의 달력 아이콘은 선택 UI를 뜻한다. `PATCH /guardian/profile`은 `name`, `birthDate`, `loginId`, `profileImageMediaRefId`, `elderRoles`를 받아 전달된 필드만 수정한다. **추가(2026-08-31, 사용자 결정)**: 디자인 화면에는 드러나지 않지만, 같은 API에서 `phone`도 선택적으로 변경한다.
> 어르신 등록의 `생년월일` 미수집도 서버 `birthDate`가 nullable이라 **문제 없음**.

## 3. 🟢 일치 확인 (조치 불필요)

- **PIN 로그인**: `POST /auth/login` 이 `password`/`pin` 지원
- **감정 최대 2개**: `EmotionRequest @Size(max=2)`. 디자인 6종(사랑·그리움·보고싶음·행복·즐거움·슬픔) ⊂ 서버 enum
- **가족**: 생성+초대코드(D4), 4명 상한(FAMILY_CAPACITY_EXCEEDED), 합류(코드), 우리 가족 구성원·역할(`GET /families/my`)
- **추억 등록**: 어르신 선택·제목·사진 4장(`@Size(max=4)`)·메모·여쭤볼 한마디(message)·연도(memoryYear) 필드 매칭
- **추억 상세 답변**: 음성/감정/이미지 재생·표시(`GET /guardian/memories/{id}/responses`)
- **리포트 6종**: 목록·요약·출석(7일+연속+월횟수)·인지 영역별 3색 상태(4영역)·이번 주 하이라이트·서포트 가이드 + PDF
- **하루 한마디**: 음성/텍스트 전송(`/daily-care/text`·`/voice`), 어르신 수신함(`/elder/inbox`)
- **어르신 홈**: 오늘의 인지 활동·새 추억·하루 한마디 카드(`ElderHomeResponse`)
- **어르신 답변(음성/감정/이미지)**: `/elder/memories/{id}/responses/voice·emotion·image`
- **보호자 홈**: 주간 스택 차트(답변/추억 열람/한마디 읽음/인지 훈련 = `DayActivityResponse`)·오늘의 할일(오늘의 한마디/추억 등록 = `Challenge`)·마지막 접속(lastLoginAt)
- **미디어 업로드**: `/media/upload-request`·`/media/{id}/confirm`

## 4. ⛔ 서버엔 있으나 확정 디자인에 없음 (미사용 — 정리/보류 판단)

| 서버 기능 | 상태 |
| --- | --- |
| 이메일 인증 (`POST /auth/email-verifications`, `.../confirm`) | 디자인 회원가입에 이메일 자체가 없음 → 미사용 |
| AI 회상 "오늘의 이야기" (`GET /elder/reminiscence/today`) | 대응 화면 없음 |
| 인지 훈련(CIST) 문항 진행 화면 | 홈 "활동 시작하기"·홈 기록엔 언급되나 **문항 UI 화면이 디자인에 없음** → 별도 확인 |
| 하루 한마디 보낸 이력 (`GET .../daily-care/sent`) | 보낸 이력 화면 없음 |
| 어르신 텍스트 답변 (`POST .../responses/text`) | 답변 방식은 말하기·마음·사진 3종뿐(텍스트 없음) |
| 감정 `ANGRY(분노)` | 디자인 6종에 없음 |

## 6. 구현 동기화 상태 (2026-08-27)

`design-api-spec.md`의 확정 결정을 기준으로 아래 항목을 구현·검증했다.

| 원래 갭 | 반영 결과 |
| --- | --- |
| M1 | `GET /auth/login-id/availability`를 인증 없이 노출하고 `{loginId, available}` 반환. 보호자·어르신 최종 등록의 유니크 경합도 `409 LOGIN_ID_ALREADY_TAKEN`으로 변환. |
| M2 | 보호자 활동 타임라인을 `date`와 5개 활동 타입·상세 필드 계약으로 구현. 잘못된 날짜는 `400 INVALID_INPUT`. |
| M3 | 홈 어르신 카드에 `condition: GOOD\|CAUTION\|OBSERVE\|null` 추가. 인지영역 중 최저 상태를 사용하고 판정 데이터가 없으면 `null`. |
| M4 | `elderId` 없는 목록 조회를 전 어르신 통합 조회로 지원. 항목의 `elderId`로 소속을 식별. `elderName`은 원 문서의 권장 항목이라 추가하지 않았다. |
| M5 | 하이라이트 조회·편집을 `items[{id,title,body}]` 계약으로 구현. ID가 없는 신규 항목은 서버가 생성한다. |
| X1 | 보호자 가입의 `phone`·`email`·`emailVerificationId`를 선택값으로 완화. 인증 ID가 전달된 경우에만 검증된 이메일을 소비한다. |
| X2 | 어르신 등록은 필수 6자리 `pin`, 선택 `password`로 변경하고 PIN 로그인을 검증. |
| X3 | 답변 조회에 `createdAt`, `mediaUrl`, `durationSeconds`, `transcriptionStatus`를 노출하고, 음성의 `text`에는 Gemini 비동기 전사를 매핑. `PENDING`·`FAILED`에서는 `text=null`이며 음성 재생은 계속 가능하다. |
| X4 | 추억 등록·수정·목록·상세에 선택 `place`, `memoryMonth`(1~12)를 추가. |

§4의 이메일 인증, AI 회상, CIST, 보낸 이력, 어르신 텍스트 답변, `ANGRY`는 `design-api-spec.md` Part C 결정대로 제거하지 않고 유지한다.
