# 해미 v2 — 기능 백로그

> 기준: [v2-functional-spec.md](./v2-functional-spec.md) · [v2-work-assignment.md](./v2-work-assignment.md)
> 최초 작성: 2026-08-22
> 목적: 기능 ID 기준 개발 진행도 및 담당자 추적
> 운영 파일명: `BACKLOG.md`

이 문서는 **기능명세의 기능 단위 진행 상황**을 추적합니다.

- 정식 기능 ID가 있는 항목은 **기능 ID를 기준으로 완료도를 계산**합니다.
- 기능명세에 세부 기능 ID가 아직 없는 항목은 `ID 미부여 기능`에 별도 기록합니다.
- 하네스, 공통 토대, 배포 등 기능 ID에 직접 대응하지 않는 작업은 `기반 작업`에서 따로 관리합니다.
- PR이 머지될 때 담당자는 해당 행의 상태·진행률·PR을 함께 갱신합니다.
- 기능 ID 또는 명세 내용은 이 백로그에서 임의로 만들거나 변경하지 않습니다.

### 구현 경계·후속 결정

- 현재 콘텐츠 선택기는 최근 7일 제외·풀 고갈 시 재사용·마지막 노출이 오래된 항목 우선을 구현했다. 명세의 **14~30일 재투입 창**은 범위만 있고 세션별 재투입 시점 선택 규칙이 없어, 운영 정책을 확정한 뒤 적용한다.
- API는 `inactivityReminderSeconds: 90`을 내려준다. 실제 무입력 음성 재안내 타이머와 음성 재생은 어르신 앱의 책임이다.
- 지남력 날짜는 서버 KST 기준으로 생성한다. 기기 날짜를 별도 기준으로 받아야 한다면 신뢰 모델·오프라인 허용 여부를 먼저 확정한다.

# 9. PR에서 백로그 갱신하는 방법

PR을 열 때 해당 기능의 행을 다음처럼 갱신합니다.

```md
| `CIST-TRN-001` | 인지 훈련 시작 | 김연호 | 🟨 진행 중 | 40% | #123 | 세션 생성/이어하기 구현 중 |
```

리뷰 요청 시:

```md
| `CIST-TRN-001` | 인지 훈련 시작 | 김연호 | 🟦 리뷰 중 | 95% | #123 | 테스트 포함, 리뷰 대기 |
```

머지 후:

```md
| `CIST-TRN-001` | 인지 훈련 시작 | 김연호 | ✅ 완료 | 100% | #123 | DoD 통과 |
```

차단 시:

```md
| `HOME-???` | 하루 한마디 수신 | 황정빈 | 🚫 차단 | - | - | 읽음 처리·보관 기간 명세 필요 |
```

단, **없는 기능 ID를 실제 ID처럼 만들어 쓰지 않습니다.** 위 `HOME-???`는 예시 표기일 뿐이며 실제 백로그에서는 기능명으로만 관리하다가 기능명세에 ID가 확정되면 교체합니다.

# 10. 갱신 원칙

1. **기능명세가 기준**입니다. 백로그가 명세를 덮어쓰지 않습니다.
2. 기능 ID를 임의 생성·변경하지 않습니다.
3. PR 하나가 여러 기능 ID를 건드리면 관련 기능을 모두 표시하되, 가능하면 기능 단위 PR을 우선합니다.
4. 진행률은 코딩량이 아니라 **완료 조건 충족 정도**를 기준으로 적습니다.
5. `✅ 완료`는 머지 전에는 사용할 수 없습니다.
6. `⏸ 대기`, `🚫 차단`은 완료율 분모에서 제외하고 사유를 반드시 적습니다.
7. 담당자가 바뀌면 업무분담 문서와 이 파일을 같이 갱신합니다.
8. 황정빈은 하네스/백로그 구조를 관리하고, **각 담당자는 자기 기능 상태를 직접 최신화**합니다.
9. 릴리스 전에는 GitHub PR/브랜치 상태와 이 문서가 일치하는지 두 사람이 함께 확인합니다.
